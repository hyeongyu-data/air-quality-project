# ADR-0004. 왜 규칙 엔진인가 — 임계값 표가 곧 도메인이다

- 상태: 채택 (2026-07-30)
- 관련 이슈: [#52](https://github.com/hyeongyu-data/air-quality-project/issues/52)

## 맥락

판정은 `consumer/rules.py`의 임계값 표(`AlertRule` 목록)로 한다. 지수별 4단 등급(좋음/보통/나쁨/매우나쁨 + 결측 시 정보없음)과 행동 그룹(마스크_필수, 외출_자제 등)이 전부 코드에 선언돼 있다.

"ML로 예측하지 않는 이유"를 묻는 것이 자연스러운 지점이다.

## 결정 근거

1. **임계값이 이미 공인돼 있다** — 미세먼지 등급(30/80/150), 자외선 지수(2/5/7), 강수확률 구간은 환경부·기상청이 정의한 공식 기준이다. 이 도메인에서 판정 로직의 가치는 예측 정확도가 아니라 **공식 기준의 정확한 반영**이다.
2. **설명 가능성이 요구사항이다** — "왜 마스크를 쓰라고 했나?"에 "PM10 82로 나쁨 구간(80 초과)"이라고 답해야 한다. 알림의 신뢰는 근거 제시에서 온다.
3. **예측은 상류가 이미 한다** — 강수확률·기온은 기상청 예보 API가 주는 값이다. 그 위에 다시 모델을 얹는 것은 예측의 예측이다.
4. **데이터가 없다** — 하루 4건, 라벨 없음. 학습할 것도 검증할 것도 없다.
5. **테스트 가능성** — 순수 함수 판정이라 경계값 테스트로 완전히 고정된다(`tests/test_rules.py`). 이 프로젝트 회귀 테스트의 뼈대다.

## 규칙 엔진에서 실제로 어려웠던 것

임계값 비교 자체가 아니라 그 주변이 전부였다. 이것이 "규칙 엔진 = 쉬운 선택"이 아닌 이유다.

- 결측을 0으로 치환하면 "체감온도 0℃ → 동상 위험" 오탐이 나간다 → `UNKNOWN` 등급 분리 (#33)
- 프록시 값(PM10→황사)은 임계 척도가 달라 죽은 지표가 된다 (#44)
- "없음"(확인된 정상)과 "정보없음"(수집 실패)은 다른 상태다 (#33)

## 검토한 대안

| 대안 | 탈락 이유 |
| --- | --- |
| ML 분류/예측 | 위 1·3·4. 공인 기준이 있는 도메인에서 모델은 근거를 흐린다 |
| 외부 룰 엔진 (Drools류) / 설정 파일(YAML) 규칙 | 규칙이 9지수 × 4구간으로 작고 변경 주체가 개발자뿐이다. 코드 밖으로 빼면 타입 안전과 테스트만 잃는다 |

## 재검토 조건

- 개인화(사용자별 민감도)나 "내일 나쁨 예상" 같은 자체 예측 요구가 생기면 → 판정(규칙)과 예측(모델)을 분리해 예측 결과를 하나의 입력 지수로 추가한다. 규칙 엔진은 그대로 최종 판정을 맡는다.
- 규칙 변경 주체가 비개발자로 넓어지면 → 임계값만 설정 파일로 추출한다.
