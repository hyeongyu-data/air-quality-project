기술 선택

과잉은 인정하고, 근거와 재검토 조건을 기록합니다

선택이유재검토 조건
Kafka 규모(하루 4건)가 아니라 장애 격리와 백로그 재생이 근거 실배포 시 SQS 교체
OpenSearch 판정 이력 탐색과 공유 상태 저장을 하나로 대시보드 요구가 없으면 SQLite로 강등
규칙 엔진 임계값이 환경부·기상청 공인 기준 — 예측이 아니라 정확한 반영이 가치 자체 예측 요구 시 모델을 입력으로 추가
로컬 Docker 모든 코드를 제3자가 재현·검증 가능하게 — 검증 불가한 코드는 삭제 실사용자 상시 제공 시 AWS 이전

운영 품질

Docker에서 장애를 실제로 일으켜 검증

  • 재생성 내구성토픽·오프셋·DAG 상태·이력이 down/up을 넘어 유지
  • 장애 복원브로커·저장소가 죽어도 백오프 재연결, 쿨다운은 로컬 캐시로 유지
  • 수명 관리SIGTERM 1초 내 정리 종료, 하트비트로 루프 생존 감시
  • 보존 정책Kafka 72시간 · OpenSearch 90일
  • CI 게이트169 테스트 + 커버리지 바닥 + compose 검증이 머지 조건
  • 계약 테스트공공 API 응답을 픽스처로 고정 — 스키마가 바뀌면 CI가 먼저 깨짐
  • 결정 기록ADR 5편 · 트러블슈팅 기록 · 운영 리스크 문서
  • 진행 중메트릭·구조화 로깅 · 스키마 계약+DLQ · README 실행 증거

만든 과정

실무·아키텍처·SRE·채용 네 관점으로 진단부터 해서 결함 28건을 등록했습니다. "결측이 0이 되어 한여름에 동상 경고가 나간다" 같은 P0 6건이 있었습니다.

의존 순서로 고쳤습니다 — 오알림·실패 은폐를 먼저, 그다음 영속성과 멱등성, 그다음 측정과 문서. 전부 Docker에서 장애를 재현해 검증했고, 테스트는 18개에서 169개가 됐습니다.

실행된 적 없는 AWS 코드는 근거를 남기고 삭제했습니다. 검증할 수 없는 코드를 두지 않는 것도 설계 결정입니다.
